# Fixes after the code review of 4 Nov 2026

Each fix has a regression test in `tests/test_fixes.py` (or the file named). Backend: 133 tests pass, lint clean,
integrity checker 12/12 OK on the rebuilt development database. Frontend: 15 unit tests pass, production build clean.

| # | Problem | Fix | Where |
|---|---|---|---|
| 1 | Sixth state seeded as Meghalaya; the proposal submitted to NABARD says Odisha (Koraput) | Odisha + Koraput district in the seed; `SIXTH_STATE` recorded as decided from the proposal | `app/seed/demo.py`, `app/seed/decisions.py` |
| 2 | Password-reset token returned in the API response unless `APP_ENV=production` – a missing/misspelt setting exposed every account | `APP_ENV` defaults to `production`; token (and demo seeding) only in an explicitly named `local`/`development`/`test` environment | `app/core/config.py`, `app/api/v1/auth.py`, `app/seed/__main__.py` |
| 3 | Review tasks, single results and calculation runs ignored the user's geography | Same area rule as the results list: scoped users see items in their area plus tasks they submitted or are assigned; applies to list, detail, every task action, record history and the dashboard task list | `app/services/mrv.py`, `app/api/v1/mrv.py`, `app/api/v1/dashboard.py` |
| 4 | Programme targets could be overwritten in place | Value/unit/period/version locked on edit; `POST /programme-targets/{id}/revise` records the next version; duplicate versions refused; UI "Change the target figure" option | `app/api/v1/programmes.py`, `app/schemas/programme.py`, frontend `programmes.ts` |
| 5 | Adoption counted differently by the indicator, report funnel, inclusion section and dashboard breakdown | One shared rule (`reports_v2.adoption_query`) = the adoption indicators' rule | `app/services/reports_v2.py`, `app/api/v1/dashboard.py` |
| 6 | Funnel "reached" and "participating (surveillance)" not limited to the programme | Programme filter on every funnel stage | `app/services/reports_v2.py` |
| 7 | Correcting a sample visit from "confirmed" to "not visited" left the practice verified | Practice status follows its latest conclusive visit result; none left → unverified | `app/services/verification.py` |
| 8 | After sign-out, the next user in the same tab saw the previous user's cached lists | Lookup cache belongs to the signed-in user and is cleared when the user changes | frontend `core/lookups.service.ts` |
| 9 | One unexpected error in an imported record failed the whole batch | Any per-record failure is quarantined with a readable reason; the rest of the batch is saved | `app/services/integration/pipeline.py` |
| 10 | "Must change password" only enforced on screen | Server refuses everything except the profile and password change; UI redirects to Profile, then to the dashboard | `app/core/deps.py`, frontend `guards.ts`, `auth.interceptor.ts`, `shell.ts`, `auth-pages.ts` |
| 12 | State-wise targets of proposal §5.1 missing | Seeded as state targets (sum 6,500 households / 3,000 ha); reports use the area's own target and label its area | `app/seed/demo.py`, `app/services/reports_v2.py`, `reports.py`, `report_export.py` |
